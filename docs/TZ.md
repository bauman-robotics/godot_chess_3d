## 2. Среда и ограничения (проверено, не предположения)

- **Godot 4.6.2 stable** лежит в корне проекта (`Godot_v4.6.2-stable_linux.x86_64`), установлен как бинарник, не через систему.
- **GPU нет.** `/dev/dri` отсутствует, экран недоступен. Рендер идёт через **llvmpipe** (Mesa 26.0.3, LLVM 21), Vulkan — lavapipe 1.4.
- Замеры на этой машине (1920×1080, 30 fps, 40 объектов с тенями):
  - **Compatibility (OpenGL):** ~0.13 с/кадр → ролик 3:00 ≈ **12–18 мин**.
  - **Forward+ (Vulkan/lavapipe):** ~1.0 с/кадр → **1,5–2,5 часа**. Зато доступны SSAO, DOF, объёмный туман, нормальный glow.
- Вывод кадров: `--write-movie` (Movie Maker). Пишет AVI/MJPEG или PNG-секвенцию. Звук в AVI — PCM-дорожка (пригодится для черновой синхронизации).
- ffmpeg 8.0.1 + libx264/libx265/libvpx + libass/drawtext — есть.
- Python 3.14, сети есть, numpy/PIL/python-chess нет (поставим по необходимости).
- Шрифты с кириллицей: DejaVu Sans / Condensed, Lato, Liberation. За стильным шрифтом (Oswald/Inter) можно сходить в Google Fonts.

**Следствие:** превью гоним на Compatibility быстро, финал — на Forward+ в фоне. Это штатный пайплайн, не костыль.

### Про MCP

Официального MCP-сервера у Godot **нет** — Godot Foundation его не выпускает. Есть community-проекты: [godot-mcp в Asset Library](https://www.godotengine.org/asset-library/asset/5245), [Godot Editor MCP (pip)](https://pypi.org/project/godot-editor-mcp/), [обзор 2026](https://www.summerengine.com/blog/godot-mcp-servers-guide). Все они — обёртки над editor/CLI и требуют запущенного редактора с плагином.

**Нам MCP не нужен.** Задача — «отрендерить по нотации», а не «покликать в редакторе». Надёжнее и быстрее: Godot CLI в режиме Movie Maker, сцена и таймлайн — обычные файлы проекта. MCP прикрутим позже, если захочется интерактивно крутить камеру из чата.

## 3. Визуальный стиль: «тёмная студия»

Не «шахматный клуб с дубовыми панелями» и не «неон». Тёмный кинозал, где доска — единственный источник смысла и света.

**Доска.** Клетка 1.0 юнита, поле 8×8, рамка 0.45 с латунной инкрустацией. Тёмные клетки — морёный орех `#4A3527`, светлые — клён `#D8C6A5`. Roughness 0.42, clearcoat 0.15: сатин, а не лак. Координаты a–h / 1–8 — `Label3D`, выгравированы в рамке.

**Фигуры.** Процедурные, генерируются в рантайме (`SurfaceTool` + лате-профиль), без внешних ассетов и лицензионных вопросов. Силуэт — стилизованный Стаунтон: тяжёлое основание, тонкая шейка, читаемая голова. Белые — слоновая кость `#EDE6D6` (roughness 0.35), чёрные — эбен `#141414` (roughness 0.28). Конь — самый сложный: сборка из профилей + вырезанная голова.

**Свет.** Три источника:
- key: тёплый 4000K сверху-слева, мягкие тени (PCSS / мягкий фильтр);
- rim: холодный 6500K справа-сзади, обводит силуэты;
- fill: 2700K снизу, 5% интенсивности, чтобы чёрные фигуры не превращались в кляксы.

**Атмосфера.** Циклорама-фон, туман 0.02, виньетка, лёгкое зерно (film grain через шейдер постобработки — в Compatibility делается вручную). Пылинки в луче света — `GPUParticles3D`, 200 штук.

**Палитра ролика.** Уголь и латунь. Красный появляется ровно три раза: при 9...hxg6 (открылась линия h), при 11.b3 (предупреждение) и на мате. До этого — только тёплый и холодный.

## 4. Камера

Жёсткое правило: **камера всегда со стороны чёрных**, z < 0. Мы смотрим на доску глазами чёрных: их фигуры — на переднем плане, белый король — лицом к нам. Ни одного кадра «из-за белых».

Геометрия: поле в центре, чёрные — на z = −3.5, белые — на z = +3.5, файл h — слева в кадре (x = −3.5). Мат происходит в дальнем левом углу — максимально далеко от камеры и от «своего» края. Это работает драматургически: угроза приходит из глубины.

| План | Что это | Параметры |
|---|---|---|
| **P1 «Пыль»** | макро у самой доски, силуэты фигур, пыль в луче | h = 0.35, FOV 24, тревеллинг 0.5 юнита/4 с |
| **P2 «Журавль»** | подъём от кромки доски к общему плану | h: 0.8→4.2, наклон 8°→32°, FOV 45, ease-in-out |
| **P3 «Через плечо»** | базовый игровой план | поз. (0.8, 2.1, −7.6), target (0, 0, 0.6), FOV 42 |
| **P4 «Макро-вставка»** | крупный план фигуры перед ходом | дистанция 2.2, FOV 26, h = 1.2 |
| **P5 «Проводка»** | камера едет вместе с фигурой | параллельно ходу, сохраняет фигуру в кадре |
| **P6 «Коридор h»** | долли по открытой линии h, от h8 к h2 | h = 1.4, 4.5 с, лёгкий наклон |
| **P7 «Наезд»** | медленный push 5% за 3 с | усиливает «сейчас что-то будет» |
| **P8 «Орбита»** | 140° вокруг h2 | радиус 3.2, h: 1.6→2.4, 4 с |
| **P9 «Сверху»** | строго верхний план для эпилога | 90°, фигуры растворяются |

Между планами — не «склейка», а **мотивированные переходы**: камера всегда либо продолжает движение, либо режет на контрасте масштаба (общий → макро). Никаких случайных склеек.

## 5. Анимация

| Событие | Тайминг | Детали |
|---|---|---|
| Ход | 0.50 с | подъём 0.18, ease-in-out cubic, посадка с отскоком 3% (0.06 с) |
| Ход коня | 0.55 с | дуга 0.35, наклон корпуса 6° в полёте |
| Взятие | 0.60 с | удар на 0.36 с, вспышка 2 кадра, пыль, падение съеденной фигуры 0.55 с с отскоком |
| Рокировка | 0.45 с ×2 | король и ладья одновременно, ладья «перепрыгивает» короля по дуге |
| Шах | 0.8 с | пульс красного кольца на клетке короля, виньетка +8% |
| Мат | 4.5 с | замедление 0.15× на последних 8 кадрах полёта ферзя, фриз 250 мс, падение белого короля 1.2 с, орбита |

Правило: **физика преувеличена на 20%** — чуть больше инерции, чуть больше отскока, чем в реальности. Достаточно, чтобы читалось как кино, недостаточно, чтобы стало мультиком.

## 7. HUD и текст в кадре

- Нижняя плашка: реплика, шрифт DejaVu Sans Condensed (или Oswald после скачивания), 42 px, разрядка, появление 0.25 с, исчезновение 0.25 с.
- Левый верх: SAN текущего хода + номер.
- Правый верх: eval-bar + часы.
- Всё рисуется **внутри Godot** (`CanvasLayer`), а не вшивается ffmpeg'ом: так гарантирован кадр-в-кадр с анимацией.
- `subtitles.srt` генерируется из того же JSON с репликами — для будущей озвучки.

## 8. Звук (задел под озвучку)

Сейчас ролик немой. Заранее готовим:
- `cues.json`: таймкоды реплик и событий (ход, взятие, шах, мат) — чтобы монтажёр/озвучка попадали в кадр.
- Черновые SFX генерируются ffmpeg'ом (щелчки фигур — короткие шумовые всплески с фильтрацией, гул, удар на мате). Не финал, но ролик перестаёт быть мёртвым.
- Дорожку голоса подкладываем позже: `ffmpeg -i video.mp4 -i voice.wav -c:v copy` — пересборка занимает секунды, рендер не нужен.

## 9. Пайплайн

```
pgn ──> tools/parse_pgn.py ──> data/game.json   (from/to, фигура, взятие, шах, мат, часы)
                                    │
data/shotlist.json ─────────────────┤
data/captions_ru.json ──────────────┤
                                    ▼
                          godot --write-movie  (PNG-секвенция)
                                    │
                            ffmpeg ─┴─> mp4 (CRF 16, yuv420p, faststart)
```

- Партия в Godot **не играется**, а проигрывается по фиксированному таймлайну: кадр N ↔ состояние на момент T. Детерминизм, повторяемость, отсутствие физики.
- Позиции после каждого полухода сверяются с эталонными FEN (тест в `tools/verify.py`), чтобы не отрендерить красивую, но неправильную партию.

## 11. Риски

1. **llvmpipe медленный и капризный.** Forward+ может падать на объёмном тумане/SSAO — держим переключатель на Compatibility без потери композиции.
2. **Нет DOF в Compatibility** — макро-планы спасаем длинным фокусом и композицией; в финале на Forward+ DOF будет.
3. **Первый кадр долгий** — компиляция шейдеров на CPU-Vulkan; в таймлайн добавляем «прогрев» вне записи.
4. **Шрифты и кириллица** — проверяем на M0, при проблемах берём DejaVu Sans Condensed (гарантированно есть).
5. **Точность партии** — тест по FEN после каждого хода.

## 12. Решения (согласовано)

1. **Хронометраж:** полный, ~3:00 (18 планов).
2. **Стиль:** «тёмная студия» — уголь, латунь, три источника света, красный акцент только на угрозе.
3. **Сарказм:** титры в кадре сейчас + `.srt` и `cues.json`; голос подкладывается позже без перерендера.
4. **Финал:** 1080p30, Forward+ (SSAO, DOF, туман), рендер в фоне ~2 ч. Превью — 720p24 Compatibility.

### Как это реализовано (по факту)

- Финал: 1920×1080, Forward+, MSAA выключен (на llvmpipe 4× MSAA стоил ~2,3× времени кадра),
  сглаживание — FXAA. Замер: 0,14–0,86 с/кадр в зависимости от плана.
- Превью: 1280×720, Compatibility, ~0,5 с/кадр (рендерилось параллельно с другими задачами).
- Movie Maker пишет AVI/MJPEG + PCM; ffmpeg пережимает в H.264 CRF 15.
- Пыль в луче — `CPUParticles3D` с радиальным спрайтом; облака-квады с первого раза
  вышли размером в кадр — уменьшены до 0,05 юнита.
- Падающие фигуры какое-то время улетали в небо: поворот считался вокруг пивота,
  но позиция узла не учитывала смещение фигуры от него. Формула исправлена:
  `position = R * (pos - pivot) + pivot`.
